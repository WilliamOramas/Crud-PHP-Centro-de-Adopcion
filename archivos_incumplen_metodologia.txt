Lista de archivos que no cumplen con la metodología del proyecto (Patrón MVC y separación de responsabilidades)

El siguiente listado detalla los archivos dentro de la carpeta "views" que contienen lógica de negocio, consultas SQL, validaciones directas o manejo de sesiones (responsabilidades que deberían pertenecer a Controladores y Modelos).

1. views/mascotas_crear.php
   - Problema principal: Contiene consultas SQL (INSERT), procesamiento directo de subida de imágenes ($_FILES), captura de datos ($_POST) y validación de sesiones con redirección (header).

2. views/mascotas_editar.php
   - Problema principal: Realiza consultas a la base de datos (SELECT, UPDATE), procesa la validación de formularios ($_POST), maneja la lógica para editar imágenes y controla el flujo de sesión.

3. views/mascotas_lista_sin_cuidador_editar.php
   - Problema principal: Similar al anterior, realiza múltiples consultas SQL directas, procesa peticiones HTTP y maneja validaciones integradas en la vista.

4. views/mis_mascotas.php
   - Problema principal: Ejecuta operaciones de base de datos (SELECT mediante PDO), maneja variables de paginación integradas y comprueba directamente variables de sesión para denegar acceso y redirigir con header().

5. views/mascotas_lista.php
   - Problema principal: Uso de consultas directas (PDO select count, y listados), construye la lógica matemática de paginación y valida las sesiones.

6. views/mascotas_lista_sin_cuidador.php
   - Problema principal: Uso de sentencias SQL embebidas desde la base de datos y procesamiento de variables de autenticación.

7. views/dashboard.php
   - Problema principal: Comprobaciones condicionales de control de acceso directas (validando $_SESSION) en el front-end con ejecución de redirecciones a otras vistas. En un modelo MVC, la carga de esta vista debería ser regulada por un controlador de autenticación de inicio a fin.

8. views/header.php
   - Problema principal: Lógica de validación directa de perfiles (Admin vs Empleado) combinada directamente con marcado HTML.

Observación general a la arquitectura: 
Se detecta la ausencia de un directorio "models/", lo cual indica que la conexión a bases de datos y manipulación de registros (lógica de datos) están ocurriendo tanto en "views" como en "controllers". Para cumplir estrictamente con el patrón Modelo-Vista-Controlador, las transacciones a base de datos en controladores y vistas deberían ser extraídas hacia clases de modelos especializadas.
